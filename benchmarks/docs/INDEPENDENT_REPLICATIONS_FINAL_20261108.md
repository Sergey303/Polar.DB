# Независимые повторения выбранных сравнений Polar.DB и SQLite — завершённая серия 8 ноября 2026 года

**Статус: выполнены все 8 из 8 заранее выбранных сочетаний сценария и объёма данных; по 8 независимых парных координаторов на сочетание — 64/64 принятых пар.** Исследование ограничено одним физическим компьютером и остаётся разведочным. Этот отчёт **не** означает независимого повторения всех 19 сценариев основной сравнительной серии 4 ноября.

## Метод и версия измерений

- Протокол до первого измерения зафиксирован 8 ноября в `PROTOCOL_20261108.txt`: `PkIntLookup`, `ExternalIntLookup`, `BuildExternalIndexesOnly`, `ReopenOnly`, размеры 50 000 и 5 000 000 строк, восемь повторов на сочетание и порядок ABBA (SQLite → Polar.DB / Polar.DB → SQLite / Polar.DB → SQLite / SQLite → Polar.DB).
- Исходный код и собранные исторические Release DLL — коммит [`abbb03cdc34cff1c11e7550494f65b03dad9afd1`](https://github.com/Sergey303/Polar.DB/commit/abbb03cdc34cff1c11e7550494f65b03dad9afd1); Ubuntu 24.04.4 / WSL2 / ext4, .NET SDK 10.0.400, Runtime 10.0.11, SQLite native 3.53.3, Intel Core i5-12400 (12 логических процессоров), Server GC отключён.
- Один повтор — независимый запуск координатора, создающий свежие процессы обоих движков. Для поиска используются исходные измерения фаз и задержек; для построения/открытия — один прогрев и три внутренних измерения на координатор. Внутренние запросы одного процесса **не** считаются независимыми повторениями.
- Основная метрика поиска — среднее время запроса в пакете (batch-average), для построения — операция построения внешних индексов и завершения записи, для открытия — полный цикл с первым проверенным запросом и последующим закрытием. Отдельные индивидуальные задержки и время конструирования также приведены ниже, без замены основной метрики.
- Для каждого из восьми координаторов вычисляется отдельная пара медиан; оценка ускорения — `exp(median(ln(SQLite / Polar.DB)))`. Приведён двухсторонний 95%-й процентильный бутстреп-интервал по **целым парам** (10 000 перевыборок, фиксированный seed 20261029). Коэффициент выше 1 означает меньшую задержку Polar.DB; ниже 1 — меньшую задержку SQLite. Коэффициент не обязан равняться отношению медиан в соседних столбцах.

Это не ошибка данных и не повод скрывать показатель: см. строку индивидуальной задержки в полной таблице ниже.

При построении четырёх внешних индексов и при повторном открытии сравнение на стороне SQLite; однако физический объём подготовки индексов при открытии, операции записи и модель хранения различаются. Полученные числа **не** являются доказательством превосходства одного и того же алгоритма. Основные таблицы 1–9 статьи по исторической серии 4 ноября неизменны: новое исследование вынесено в дополнительный материал.

## Полнота и ограничения воспроизводимости

Все 64 пары имеют `combined.raw.json`, `manifest.json`, `samples.csv` и исходные JSON обоих рабочих процессов. Координатор и оба worker фиксируют один source SHA, успешную готовность к публикации, корректную парность и отсутствие изменений отслеживаемых исходных файлов на момент измерения. Манифесты восьми серий содержат по восемь принятых запусков, а пересчёт таблиц производится непосредственно из исходных JSON/CSV, не из переписанного вручную текста.

**Особенность окружения:** ранние повторы выполнены в RDC с закреплённым SDK/Runtime. После остановки из-за нехватки реального места Windows `D:` последние пять повторов построения индексов на 5 млн строк и все повторы открытия на 5 млн строк выполнялись в отдельном контейнере с точным Docker-образом SDK 10.0.400 (`sha256:4beef5b8919dcaa2dc924233bd069257e883cc7a061e09088a97d152d6a48510`) и тем же Runtime 10.0.11. Проверяемые подписи окружения (CPU, ОС, runtime, SQLite, конфигурация сборки и GC) совпадают; процессный namespace и представление часового пояса могут отличаться. Это потенциальный межгрупповой фактор, поэтому объединённые результаты трактуются осторожно.

Протокол ABBA уменьшает эффект порядка, но не гарантирует независимость файлового кэша, стабильность частоты CPU, одинаковую нагрузку на SSD и одинаковую доступную память. Все повторы выполнены на одном физическом компьютере, а восемь пар недостаточны для уверенного номинального покрытия бутстреп-интервалов. Это разведочные оценки; ранее опубликованный протокол рекомендует заранее планировать **12 и более** независимых пар на сочетание для более строгой публикационной серии. Множественность фаз и метрик требует отдельной осторожности при выделении выводов.

**Предел завершённости:** исходный план из 8 × 8 пар выполнен полностью, но это не независимая репликация на другом оборудовании, не измерение всех 19 сценариев, не проверка асимптотики и не доказательство новой универсальной индексной структуры. Исторические серии на других SHA и серия 4B с управляемой резидентностью файловых страниц не объединялись с этим исследованием.
