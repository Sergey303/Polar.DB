# Воспроизводимость научной статьи Polar.DB — переносимый стандарт

**Действует для новых запусков.** Исторические исходные CSV, журналы, протоколы и исходные SHA 2021/2026 сохранены без пересчёта «в лучшую сторону». Протокол первоначального опыта 8 ноября описывает реальную тогдашнюю среду и остаётся историческим документом. Новая система не требует ни конкретного компьютера, ни Windows-диска, ни учётной записи root.

## Уровень A: независимая арифметическая проверка статьи

Из корня полного репозитория (или с абсолютным путём к скрипту из любого каталога):

```shell
python3 benchmarks/scripts/verify-publication.py
```

На Windows вместо `python3` используйте `python` или `py -3`. Требуется **Python 3.10+**, файлы архивов из репозитория и достаточно места в стандартном временном каталоге. Не нужны Git-команды, Docker, .NET, Bash, `tar`, `sha256sum` или доступ в интернет. Процесс проверяет:

1. Целостность и происхождение опубликованных архивов, закреплённых версий и протокола.
2. Таблицы 1–9, вспомогательные таблицы и доли стадий восстановления по исходным данным (**204 ячейки**).
3. Таблицу 10 и парную статистику серии 4B (включая интервал бутстрепа).
4. Таблицу 11 по **12 историческим процессам**, включая контрольные суммы и SHA-256 CSV.

Основная серия извлекается в **уникальный каталог операционной системы** и автоматически очищается. При ошибке любая проверка останавливает общий процесс с ненулевым кодом. Проверка архива не доказывает, что времена повторятся на другом оборудовании.

## Уровень B: независимый запуск измерительной программы

Требуются **полная история Git** (без shallow clone), Python 3.10+, Git, .NET **SDK и Runtime 10.x**, место и память для обеих исторических сборок. Скрипт берет именно следующие исходные коммиты:

- апрель 2021: `39cefe13db8697cf5f8e15edaa4677ba52a2cdea`;
- ноябрь 2026: `09ec0703f476f25ec79baff338843df8a8e83b35`.

```shell
python3 benchmarks/scripts/run-index-evolution-direct.py --mode smoke
python3 benchmarks/scripts/run-index-evolution-direct.py --mode full
python3 benchmarks/scripts/run-index-evolution-direct.py --mode full --output /choose/new/directory
python3 benchmarks/scripts/run-legacy2021-replay.py 10000 1000 777
```

В `full` фиксированы 50 000 и 1 000 000 записей, **1000 запросов, seed=777 и три парных блока на размер**. Порядок меняется `2021→2026`, `2026→2021`, `2021→2026`. `smoke` допускает ограниченные изменения размера/числа запросов, но предназначен **только для проверки сборки и корректности**. Диагностический `Legacy2021Replay` воспроизводит другой код (ручной `Main306`), его времена не объединяются с серией внешних индексов.

Программа извлекает исходники средствами Python из неизменяемых Git-объектов. Исторической версии меняется **только целевая платформа проекта** (netstandard2.0 → net10.0), оба движка выполняются на выбранном установленном .NET 10; изменения исходников индексирования не выполняются. Дополнительные изменения адаптера стенда фиксируются SHA-256 в выходном `manifest.json`.

## Данные, остановка, сохранность

- По умолчанию выход — **новый** каталог под `benchmarks/results/index-evolution/` (он исключён из Git). Параметр `--output` задаёт **иной новый** каталог на любой доступной файловой системе, включая внешний диск; нельзя указывать существующий путь или требовать перезаписи.
- Перед сборкой и каждым измерением `shutil.disk_usage` проверяет реальное свободное место **на выбранной файловой системе** (полная серия: не меньше **2 ГиБ**). При виртуализированной ФС дополнительно контролируйте её физический backing volume: стандартные API могут сообщать только виртуальную квоту.
- Временные базы создаются через `tempfile.TemporaryDirectory` **внутри собственного каталога результатов** и удаляются только по завершении соответствующего процесса; чужие каталоги и файлы никогда не очищаются.
- При ошибке времени ожидания, сборки, парности, контрольной суммы или нехватки места сценарий останавливается. Успешные строки `results.csv`, `build-*.log`, `measure-*.log`, применённые исходные файлы и `manifest.json` сохраняются. Метка `complete` ставится только после всех запланированных процессов.
- `manifest.json` содержит исходные SHA, версии SDK/Runtime, параметры, ОС/архитектуру, признаки dirty, SHA-256 адаптеров и результаты. Вывод `verified=true` проверяется вместе с двумя полями каждой найденной записи. Внутренние поиски одного процесса не являются независимыми повторениями.

## Независимая проверка переносимости

[GitHub Actions](../../.github/workflows/research-reproducibility.yml) задаёт отдельную матрицу `ubuntu-latest`, `windows-latest`, `macos-latest` с полным fetch Git-истории, Python 3.12 и .NET 10. Она запускает unit-тесты отрицательных сценариев, всю проверку архивов, два исторических smoke-измерения. **Статус «прошло на Windows/macOS» допустим только после реального успешного CI job каждой платформы**; локальная проверка в Linux не является его заменой.

**Проверка выполнена:** [GitHub Actions run #42552314956](https://github.com/Sergey303/Polar.DB/actions/runs/42552314956), исходный коммит `bece044e2fb1ff8ed7151cc344ccd16489b2ebfd`. Все три независимых задания **Ubuntu / Windows / macOS — SUCCESS**. Во всех заданиях успешно выполнены единая архивная проверка, отрицательные unit-тесты, компиляция и smoke-поиск обоих исторических движков, а также Main306. Это подтверждает переносимость указанных сценариев в трёх GitHub runner-средах, но не тождественность времен на произвольном оборудовании.

## Научная интерпретация

Уровень A позволяет независимо **пересчитать опубликованные числа**; уровень B позволяет **вновь исполнить алгоритмы** с верификацией результатов. Они не обеспечивают совпадение миллисекунд из-за различий CPU, состояния JIT/GC, файлового кэша, ОС и накопителя. Числа новой серии не переписывают исторический `results.csv`: их сохраняют отдельно и анализируют только с указанием нового окружения и полного набора запусков.
